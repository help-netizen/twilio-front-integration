## OB-70 (2026-08-19) — Нельзя удалить/void оплаченный (частично/полностью) инвойс; платежи должны оставаться на работе; финанс-блок = суммы — **ОТКРЫТ, tandem + audit + design-qa** (владелец)

Владелец (пример инвойс J-1668-2, полностью оплачен): red-кнопка называется «Void», а в тексте «нельзя из-за баланса»; при «Void invoice» → ошибка **«Draft invoices must be deleted, not voided»** (неверно для Paid). **АУДИТ (Claude):** у J-1668-2 статус в БД = **`draft`** — принял платёж, будучи черновиком, никогда не «issued». `voidInvoice` (`invoicesService.js:778`) режет `draft`; `deleteInvoice` (`invoicesQueries.js:398`) только `draft` И осиротит платёж. → **сегодня нет пути «убрать оплаченный инвойс, сохранив платёж».** Платёж-пул уже job-centric (`paymentLedgerService` «derives paid from that job's payment pool», см. [[pay-jobcentric-001]]).

**Желаемая модель (владелец):** void/удаление инвойса (draft ИЛИ оплаченного) → платежи ОСТАЮТСЯ на работе (отвязаны от инвойса), чтобы создать новый инвойс. Новый инвойс подхватывает пул (показывает paid) ТОЛЬКО если другого инвойса нет; если другой инвойс уже есть — платежи к нему НЕ привязываются (но в job-paid считаются). Финанс-блок работы = СУММЫ: estimated = Σ активных эстимейтов, invoiced = Σ активных инвойсов, paid = Σ платежей работы (рефанды/void — исключить), due = invoiced − paid.

**РЕШЕНО владельцем (19.08):** (1) **ДА — одно «Remove invoice»** (любой статус draft/issued/partial/paid; убирает инвойс, платежи остаются на работе; чёткий confirm-текст). (2) **Вариант A:** платёж привязан к инвойсу, где сделан; remove/void → отвязка в job-пул; НОВЫЙ инвойс подхватывает пул ТОЛЬКО если он единственный; иначе платёж job-level (в job-paid считается, ни на одном инвойсе не показан); пер-инвойс «paid» остаётся. (3) over-collection (paid>invoiced) → Due отрицательный = кредит (как [[pay-jobcentric-001]]). (4) void-инвойсы исключены из Σ invoiced; void/refund-платежи из Σ paid. **Стройка (queued):** tandem — Codex бэкенд (unified remove + detach-payments + job-суммы estimated/invoiced/paid/due), Claude фронт (Remove-экшен + confirm + финанс-блок) + **design-qa** (визуал-гейт) + **audit** флоу; ПОСЛЕ завершения+коммита OB-69 (общие invoice-файлы: `invoicesService.js`/`invoicesQueries.js`).

**RESEARCH (Claude, 19.08) — HCP / Jobber / Workiz / QuickBooks:** индустриальный стандарт = **«unapplied payment / account credit»**: платёж живёт на клиенте/работе, состояние applied/unapplied; при удалении инвойса платёж становится **unapplied-кредитом** (Jobber: «applied to account balance», не исчезает; QBO: «unapplied cash»); **void только НЕОПЛАЧЕННЫХ** инвойсов (сначала отвязать платёж → потом void пустого); повторная привязка — **вручную/подсказкой** (открыть платёж → apply к выбранному инвойсу), НЕ тихий авто-матч; **никогда не удалять reconciled-платёж** (ломает сверку) — держать как кредит. Источники: help.getjobber.com Invoice-Basics/Billing-History; help.housecallpro.com delete-a-payment; help.workiz.com Deleting-an-invoice; QuickBooks unapplied-cash.

**УТОЧНЁННЫЕ правила владельца (супер­седят п.2 выше):** при удалении частично/полностью оплаченного инвойса платежи отвязываются и ищут «родителя» по приоритету: (1) инвойс на сумму платежа; (2) инвойс, чей **ДОЛГ** (balance due, не total) = сумме всех неотвязанных платежей (напр. $95+$100=$195 → инвойс с долгом $195, м.б. крупнее и частично оплачен); (3) иначе — любой частично/неоплаченный инвойс, даже если платёж превышает его сумму.

**ПРЕДЛОЖЕНИЕ Claude (сверить с владельцем):** платёж = job-level с `applied_invoice_id` (applied → paid этого инвойса; unapplied → job-кредит, всегда в job-paid). Remove-invoice → платежи в unapplied-кредит (не теряются), инвойс void(audit)/delete(draft). Кредит можно применить к ЛЮБОМУ инвойсу (существующему/новому) в любой момент — снимает боль «создал новый до удаления». Правила 1-3 = **дефолт-подсказка** в «Apply payment», а не тихий авто-матч (риск мис-атрибуции денег). **РАЗВИЛКА:** авто-применять молча (буквально п.1-3) vs предлагать-и-подтвердить (безопаснее; авто только при однозначном единственном совпадении). Рекомендую второе. → **РЕШЕНО владельцем (финальный флоу):** при Remove инвойса с платежами система ищет ДРУГОЙ инвойс-кандидат (неоплаченный / с долгом, по приоритету правил 1-3). **Если кандидат ЕСТЬ → ВСЕГДА спрашивает диспетчера явно:** «Привязать $X из удаляемого инвойса к Invoice #Y ($Z)?» — пользователь сам выбирает привязать/нет (НЕ тихий авто-матч даже при единственном совпадении). **Если все другие инвойсы оплачены ИЛИ их нет → платежи молча отвязываются** (unapplied job-кредит, всегда в job-paid).
